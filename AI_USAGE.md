## Where the AI was wrong and how it was caught (all real, found in this audit)
1. **Hard-coded benchmark numbers.** The first `benchmark.py` printed LLM accuracy 72.3%, 1,450 ms, $0.75 as constants, and `task5_law_change.py` hard-coded "15/25/45 minutes" and "0 silent failures". Nothing had been run against Gemini (the project README even said so). Caught by reading the code against the claimed results. Fix: the benchmark computes everything and prints NOT MEASURED when it cannot.
2. **Circular test oracle.** Expected taxes were generated by implementation (a) itself, so "100% accuracy" proved nothing. Caught by tracing the generator. Fix: independent oracle written differently; a random 32,000-evaluation comparison then exposed a real bug in the compiled FY25-26 spec (surcharge steps collapsed into one) and that FY25-26 rule text had no clause IDs, so every FY25-26 answer failed traceability.
3. **Project B was circular and synthetic.** The "LLM" detector was a keyword list matching the injector's own sentences, the near-duplicate detector looked for the literal text the injector appended, and the "NYC 311" file was generated data presented as real. Fix: no markers in the injector, detectors learn from a reference, LLM family only runs live, data labelled SYNTHETIC with a real fetcher.
4. The original AI_USAGE narrative cited a `test_suite.py` that does not exist and a bug that was not in the repo history; it was removed. Keep only incidents you actually saw.
